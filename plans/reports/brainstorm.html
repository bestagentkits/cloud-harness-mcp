Hợp đồng định vị kiến trúc 5 Hard Gates, so sánh đối chiếu nhánh (Branch Comparison: 7bcdd9e vs HEAD v0.30.0) và lộ trình tích hợp / nghiệm thu Canary để đóng hoàn tất Issue #19.

🎯 1. Outcome (Trạng thái đích)

Cung cấp bộ 6 MCP tools cho phép caller điều khiển subagent Pi chạy trong workspace:

  • agent_spawn: Khởi tạo subagent có budget, TTL, model profile, gắn chặt với workspace/principal.
  • agent_status: Tra cứu trạng thái, metrics sử dụng, terminal reason & outcomeUnknown.
  • agent_logs: Đọc log streaming/phân trang bằng cursor có redaction trước lưu.
  • agent_message: Gửi chỉ dẫn steer hoặc followUp vào session đang chạy.
  • agent_cancel: Hủy theo cây (post-order cascade) có hàng rào thu hồi tài nguyên sạch.
  • agent_list: Liệt kê các agent thuộc quyền sở hữu, hỗ trợ phân trang & bộ lọc.
✓ Invariant cốt lõi
Subagent là untrusted workload; chạy trong container riêng, không có Docker socket, không repository mount, không credential control-plane và không Internet egress tổng quát.
🛡️ 2. Constraints (5 Hard Gates Bắt buộc)
  • HG1 (No Host/Control Access): Dedicated container non-root, read-only rootfs, tmpfs quota, zero host/repo mounts, zero secrets.
  • HG2 (Strict Network & Admission): Workspace giữ nguyên networkMode: none (từ chối spawn nếu workspace là bridge). Agent chỉ nối Model Gateway qua mạng nội bộ riêng.
  • HG3 (Exact 10 Tools & Pi Lockdown): Đúng 10 safe operations được liệt kê tường minh: files_list, files_read, files_write, files_apply_patch, files_delete, files_move, files_mkdir, grep_search, symbols_search, symbols_references. (Lưu ý: files_write_batch được chủ ý loại trừ nhằm giảm thiểu bán kính đột biến mã nguồn trên từng lượt gọi — mutation blast radius — và giữ chính sách công cụ của agent đơn giản, tập trung vào chu trình chỉnh sửa từng file có hash guard qua files_write / files_apply_patch). Khóa hoàn toàn Pi built-ins, extensions, prompts, context discovery và nested spawn.
  • HG4 (Cascading Cleanup Barrier): Revoke lease → Drain requests → TERM/KILL → Remove container/network → Verify 0 residual trước khi xóa thư mục workspace.
  • HG5 (SQLite Durability & Fencing): Intent ghi trước side effect, epoch fencing chống stale write, không auto-replay khi crash, báo outcomeUnknown: true trung thực.
🚫 3. Non-goals (Ngoài phạm vi)
  • Không cấp raw shell, exec_run, Git remote push, deployment hay browser cho Pi.
  • Không cho agent tự spawn agent con (recursive autonomous spawn). Lineage chỉ do trusted caller tạo.
  • Không cho caller truyền provider URL/API key tùy ý; chỉ dùng Model Profiles cố định của operator.
  • Không tự resume/replay hội thoại Pi sau Runner crash; ưu tiên tính trung thực outcomeUnknown.
  • Không tuyên bố Model Gateway hay Docker shared-kernel là hostile multi-tenant sandbox; bảo vệ threat model private/single-owner.
✅ 4. Acceptance Criteria (Điểm nhấn nghiệm thu)
  • 32-way Idempotency: 32 requests concurrent cùng key tạo đúng 1 agent row, 1 lease, 1 container và 1 prompt.
  • Zero Residual Resources: Sau cancel/TTL/close/crash, kiểm tra Docker & Gateway chứng minh 0 container, 0 network, 0 active lease.
  • Secret Redaction: Injected secrets không bao giờ lọt vào DB, WAL, logs, MCP responses hay stdout/stderr.
  • Crash Consistency: Crash tại bất kỳ điểm nào trong crash matrix đều kết thúc an toàn, không duplicate write.
  • Parity: Schema, annotations, dispatch và E2E giữ đồng bộ tuyệt đối 6 tools & 10 proxy operations.
