🎯 Core Architectural Direction: Bounded Passive Scanner + Lightweight Hybrid State Store

Cloud Harness MCP adopts a split-plane provenance architecture: (1) Worker Passive Scanner discovers instruction files (AGENTS.md, CLAUDE.md, .cursorrules, .aider.conf.yml), language manifests, and test declarations with strict zero-execution, bounded byte budgets; (2) Runner Provenance Resolver assigns non-forgeable trust layers (built-in > owner > workspace > repository); (3) Principal-Qualified SQLite manages durable scoped memories (owner, repository, workspace) with optimistic concurrency (CAS), tags, TTL, and atomic audit logging; (4) Declarative Hooks Registry requires exact SHA-256 digest activation before running in a short-lived, no-network, no-secret executor container.

🛡️ Zero Execution on Scan

Passive discovery performs NO shell invocations, package scripts, or dynamic code evaluation.

🏷️ Immutable Provenance

Runner assigns trust labels from isolation boundaries. Repository files cannot forge owner authority.

🧠 Scoped SQLite Memory

Principal, repository, and workspace scopes with generation guards, TTL expiry, and tag search.

🔒 Digest-Pinned Hooks

Named lifecycle events (pre_commit, post_checkout) execute only in ephemeral sandboxes with exact digest matching.

📋 Bounded Delivery Contract (4 Inviolable Fields)
Authoritative Spec

🎯 1. Outcome (End State)

  • Universal Context Manifest: workspace_context returns a bounded, vendor-neutral manifest of known allowlisted instruction files discovered within declared scan bounds (such as AGENTS.md, CLAUDE.md, .cursor/rules/*.mdc, .aider.conf.yml), language manifests (package.json, Cargo.toml, etc.), declared test commands, and skill summaries across Claude, Codex, Cursor, and Aider.
  • Explicit Provenance Attribution: Every returned item clearly identifies its source (built-in, owner, workspace, repository), trust level, content SHA-256, and mutation authority.
  • Deterministic Skill Precedence: Same-name skills resolve in exact order built-in > owner > workspace > repository with shadowed candidates fully visible.
  • Durable Scoped Memories: Principal, repository, and workspace memories with CAS generation concurrency, TTL cleanup, tag filtering, and deletion.
  • Safe Lifecycle Hooks: Declarative event registry with exact digest-pinned activation, sandboxed executor isolation, and strict pre-commit veto semantics.

⛓️ 2. Constraints & Boundaries

  • Untrusted Repository Data: All checkout text, instructions, and scripts are treated as untrusted data. No repository text can elevate itself to system policy or forge owner provenance.
  • Byte-Budget Hard Caps: 32 KiB default (128 KiB max) for context manifests; 64 KiB max per memory note; max 256 scanned candidate files with 250ms deadline.
  • Principal Isolation (#13): Every SQLite query and memory record is strictly scoped by server-derived principal_id. Zero cross-principal leakage.
  • Executor Confinement: All skill/hook execution runs as unprivileged UID in isolated container with networkMode: none by default, zero access to broker tokens or Docker socket.
  • Schema Migration: Metadata SQLite schema upgrades cleanly v4 → v5 with atomic transactions and downgrade refusal safety.

🚫 3. Non-Goals (Strictly Out of Scope)

  • No Agent Reasoning Stream: Context manifest is strictly passive, bounded static file discovery; reasoning traces or active execution logs are not context primitives.
  • No LLM Semantic Vector Embeddings: No runner-hosted vector databases, semantic RAG, or embeddings calculation.
  • No Automatic Prompt Merging: Does NOT concatenate conflicting instruction files (e.g. CLAUDE.md + AGENTS.md) into one synthetic document.
  • No Host-Level Hook Execution: Hooks never execute on the host OS and never receive control-plane broker credentials.
  • No Cross-Principal Sharing: No collaborative multi-tenant memory sharing or public memory publishing.
  • No Skill Marketplace: No dynamic remote package resolution, npm installation, or remote downloading of unreviewed skills.

✅ 4. Observable Acceptance Criteria

  • Passive Discovery Proof: Sentinel executable referenced in manifests remains completely untouched during all context, skill, memory, and hook scan operations.
  • Adversarial Output-Boundary & Prompt-Injection Containment: An adversarial repository containing fake SYSTEM headers, forged provenance fields (source: built-in, source: owner), fake delimiters/NUL bytes, and prompt-injection instructions MUST:
    • In structuredContent: remain strictly nested within result.data under trust: "untrusted-executor";
    • In text projection: be rendered by a dedicated provenance-aware formatter using trusted boundary labels/delimiters and JSON-escaped strings (or serialized JSON blocks) rather than raw string flattening;
    • Never escape into top-level message, header, tool description, or audit fields, and create zero persistent/privileged SQLite memory records.
  • Precedence Verification: 4 same-name skill fixtures resolve strictly to built-in > owner > workspace > repository with shadowed candidate visibility.
  • Concurrency Guard: memories_write and memories_delete with mismatched expectedGeneration fail immediately with CONFLICT.
  • TTL & Expiry Reaping: Expired memories are invisible immediately and reaped; workspace memories vanish on workspace closure; owner memories persist across restarts.
  • Digest Pin Invalidation: Modifying a hook script file immediately invalidates its activation digest and blocks execution before process spawn.
