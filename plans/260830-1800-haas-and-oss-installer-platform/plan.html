Phase 01 • Ready to Cook

OSS 1-Click Installer & Production Compose Pipeline

Mục tiêu: Tạo script cài đặt 1-click chuẩn xác kế thừa deploy/scripts/bootstrap-vps.sh, deploy-release.sh và cloud-harness-mcp.service, clone repo vào /opt/cloud-harness-mcp/repo, build toàn bộ Docker images (executor, api, runner) qua cloud-harness-deploy <SHA>, ghi runtime.env (mode 0600) với MCP_BEARER_TOKEN, RUNNER_TOKEN, và container mount SECRET_KEYRING_FILE=/run/cloud-harness-secrets/secret-keyring.json.

Chi tiết triển khai:

  • Tạo file scripts/install.sh với kiểm tra Preflight nghiêm ngặt (RAM >= 2GB, OS Debian/Ubuntu/RHEL).
  • Clone repository vào /opt/cloud-harness-mcp/repo và cài đặt helper /usr/local/sbin/cloud-harness-deploy.
  • Sinh MCP_BEARER_TOKEN và RUNNER_TOKEN độc lập (48-byte base64).
  • Sinh host keyring /etc/cloud-harness-mcp/secret-keyring.json hợp lệ với SecretKeyringConfigSchema, cấu hình đường dẫn container SECRET_KEYRING_FILE=/run/cloud-harness-secrets/secret-keyring.json.
  • Chạy cloud-harness-deploy <SHA> để build toàn bộ image, khởi chạy systemd, xác thực readiness 127.0.0.1:3100/readyz và chạy canary probe.
  • Caddy reverse proxy chuyển tiếp về loopback ingress 127.0.0.1:3100; Cloudflare Tunnel container đính kèm mạng non-internal ingress chuyển tiếp trực tiếp tới http://ingress:3100.

Chi tiết nghiệm thu:

✓ Cài đặt hoàn tất trong < 60 giây trên Ubuntu 24.04 sạch.
✓ Build đầy đủ images (executor-image:local, api, runner) và chạy thành công canary probe.
✓ In ra đoạn mã JSON cấu hình MCP sẵn sàng copy-paste cho Cursor và Claude Desktop.

Phase 02

Outbound Node Agent, Secure Enrollment & Dedicated Tenant Orchestration

Mục tiêu: Xây dựng Node Agent kết nối outbound qua gRPC mTLS về Control Plane, cấu trúc token wire <id>.<secret>, atomic transaction BEGIN ... COMMIT với row lock FOR UPDATE, guarded consume, và hợp đồng lease epoch chống split-brain.

Chi tiết triển khai:

  • Node Agent đọc token qua --token-file /path/to/token (mode 0600, O_NOFOLLOW) hoặc --token-stdin. Tuyệt đối không dùng --token <VAL>.
  • Đọc vào zeroable Buffer, xóa file (unlink) trước khi gọi mạng, và zero buffer trong finally.
  • Bảng node_enrollment_tokens với id VARCHAR(32) PRIMARY KEY. Xác thực trong transaction: SELECT ... FOR UPDATE kiểm tra expires_at > NOW() AND consumed_at IS NULL, verify argon2.verify(row.token_hash, secret), rồi guarded update: UPDATE ... SET consumed_at = NOW() WHERE id = $1 AND consumed_at IS NULL AND expires_at > NOW() RETURNING id.
  • Hợp đồng Lease Epoch: Workspace chạy không gián đoạn trong ≤ 30s rớt mạng; quá 30s node tự freeze/quarantine. Node chỉ được resume khi Control Plane tái cấp phép lease epoch. Scheduler không được cấp phát thay thế trước hạn chót 45s.

Chi tiết nghiệm thu:

✓ Node xuất hiện trong bảng điều khiển Admin trong 5s sau khi enroll.
✓ Từ chối token sai format (400), token sai secret (401), token hết hạn (410), và token đã sử dụng (409).
✓ Kiểm thử đồng thời: 10 request cùng gửi 1 token đồng thời chỉ có đúng 1 request thành công (200) và 9 request bị từ chối 409.
✓ Kiểm thử Partition/Reconnect: Chứng minh node cũ và node thay thế không bao giờ chạy đồng thời cùng 1 workspace.
✓ Lệnh ps aux và shell history hoàn toàn không chứa secret token.

Phase 03

Hybrid Metering & Double-Entry Billing Engine

Mục tiêu: Động cơ đo lường chuẩn xác thời lượng workspace và request calls, tính năng Auto-idle sleep sau 15 phút, sổ cái tài chính kép (double-entry ledger), atomic reservation và xác thực raw-body webhook.

Chi tiết triển khai:

  • Theo dõi chính xác thời gian mở/đóng/tạm dừng của từng workspace container.
  • Cơ chế Auto-Sleep tạm dừng container khi không có request trong 15 phút, dừng tính tiền duration ngay lập tức.
  • Sổ cái kép PostgreSQL qua post_journal(...) với đơn vị 1 USD = 1,000,000 micro-USD. Đặt cọc trước (reservation) 1 giờ compute khi mở workspace.
  • Xác thực raw-body HMAC signature cho Polar.sh và Stripe; deduplicate webhook theo (gateway, webhook_event_id).

Chi tiết nghiệm thu:

✓ Mở workspace 30 phút Standard tier tính chính xác $0.04.
✓ Nạp tiền trên Polar.sh cập nhật số dư ví tức thì qua webhook an toàn.

Phase 04

Fail-Closed Firecracker MicroVM Multi-Tenant Runtime

Mục tiêu: Thực thi thang phân lập đa người dùng: Cấp VM chuyên dụng cho khách Beta, và nâng cấp Firecracker MicroVM cho phiên bản GA dùng chung với nguyên tắc FAIL-CLOSED và hạn ngạch ổ đĩa dm-thin.

Chi tiết triển khai:

  • Trừu tượng hóa ExecutionDriver hỗ trợ cả Docker (cho dedicated nodes) lẫn Firecracker.
  • Fail-Closed: Nếu thiếu /dev/kvm trên pooled node, từ chối khởi tạo ngay lập tức (không fallback sang Docker).
  • Xây dựng Firecracker microVM với kernel riêng, socket riêng theo từng jailer workspace (/srv/jailer/.../firecracker.socket), UID/GID độc lập, và mã hóa snapshot AES-256-GCM.
  • Khống chế cứng hạn ngạch lưu trữ 20GB/workspace độc quyền qua Device Mapper thin-provisioning (dm-thin).

Chi tiết nghiệm thu:

✓ Khởi động Firecracker microVM trong < 180ms qua KVM.
✓ Bài test sandbox escape chứng minh zero host access và cách ly hoàn toàn giữa các microVM lân cận.
